## Why the exe
In the e2mfc runs, 96% of main-loop entries into native code (8.7 M of 9.15 M) came from emulated exe code calling small rlmfc functions. Lifting e2mfc gave no speedup for that reason. Lifting the exe turns those calls into native-to-native calls. It is also the largest module left before the emulator can go.

## Exe facts
- Base 0x400000, entry 0x76fb04. No exports, **no base relocations**. `.text` 0x401000–0x7ca000. File offset = VA − 0x400000 − 0xa00 in `.text`.
- All sections are flagged 0xC0000040 (no execute). `.text` is treated as code by name in `functions.py` and `x86c.py`.
- `stxt774`, `stxt371`, `.MGD32` are copy-protection leftovers. Checked (H10): nothing executes there and nothing in `.text` branches there. They stay out of the lift. If that ever changes, stop and ask (census §9.1).
- No writes to exe code pages during the 80-frame run (H10 `--smc-scan` and a range probe), so entry patching is safe.

## H15/H16: the three-DLL hang (fixed by H17)
After H13+H14 the three-DLL native run hung in the main loop: lifted e2mfc `f_10118ec0` (0x101190a1 loop) walked a guest list (`[esi+0x13c]`) that had become cyclic. Its C was identical before and after H13. Cause: e2mfc 0x10104280's switch has a register bound (`mov ebx, 8` … `cmp eax, ebx; ja; jmp [eax*4+0x10104ddc]`), so the table was unresolved and its 9 case labels were address-taken "function entries". Their `fsin` kept them unlifted until H13; then the emulated switch jumped into lifted case code mid-function. H16 confirmed it: with the 16 newly liftable trig functions kept emulated, the run finishes (InitInstance 14.0 s, main loop 36.2 s, 10.7 M native calls, 4.72 M guest calls).
- Lesson: an entry that exists only because a table points at it, inside another function after an unresolved jump, is a case label. After H17 none remain in the four inventories, but check this whenever an unresolved jump remains.
- Diff mode is about 50 times slower than native (InitInstance 739 s). Give diff runs a cap of about 2 h. The report is written only at the end.
- How the spin was located: `sample <pid>` gives the native offset in the lifted function; recompile that `f_*.c` with the build's CFLAGS plus `-g` (codegen is identical) and `atos -o f.o <offset>` → C line → guest VA comment.

How the failures were found (reuse these):
- `sample <python pid>` on a hang; the lifted frame names the function. Recompile its `f_*.c` with `-g` and `atos` to map an offset to C line and guest VA (works only when the build adds no per-function flags; otherwise unreliable).
- Print the error in `native._fast_fallback` with the guest stack, `ecx`'s object and vtable (scratch copy only).

Diff a single function by restricting `enable_diff(only=...)` (scratch `DBG_DIFF_ONLY`; worth a real `--diff-only` flag).

## Open

They need an 80-bit operand that is not a double, plus RC ≠ nearest. qemu rounds such an operand to double under RC; the lifter's double model rounds it at load. **Accepted** as a limit of the double model: the game runs at 53-bit precision, MSVC6 has no 80-bit `long double`, and RC ≠ nearest only appears in short `fldcw` truncation sequences. Revisit only if a diff run shows it.
